# Ostinato — notes for Claude

Ostinato: a browser-based workstation for building sounds, recording them and sequencing them (tabs: Sequencer, Sound Lab, Capture, Instruments). Hardware lives under Instruments; the first is the user's Korg microKORG XL, supported in depth as a device module (`js/xl/`). The user wants the app framed around sounds and music, with the XL as one instrument among future ones, not the centre. The Sound Lab tab is still `lab.html` / `js/lab/`, Capture is still `recorder.html` / `js/rec/` ("Recorder" in code comments). It began as a replacement for Korg's old Sound Editor, which doesn't run on current macOS. Internal identifiers keep the old `mkxl` prefix (file formats `mkxl-seq` / `mkxl-inst` / `mkxl-bundle`, localStorage keys, the `mkxl` BroadcastChannel, `MKXL_*` environment variables): don't rename them, saved work depends on them. The user-facing overview is in `README.md`. This file covers how the code works and what we've learned the hard way.

## Working in the public repo (cloud sessions)

If this checkout is judholliday/ostinato (no `presets/MKXL_FactoryPreset.mkxl_all`, no `data/`), you're in the public repo, probably in a cloud session while the user's Mac is off:
- There is no user data, no Korg banks or MIDI spec, no Minimoog/Juno-106 data and no MIDI hardware. Tests skip what needs the banks ("0 presets round-trip" is expected). Use `?sim` (simulated XL) and `?static` (travel version), and run serve.py with `MKXL_DATA=test-data` if anything saves.
- Good work here: Sound Lab modules and sounds (check by rendering offline), sequencer logic (seqtest), styles and stock patterns, UI testable with `?sim`, tests and docs. Leave anything needing the XL, the Scarlett or the user's songs and sounds for the Mac.
- Work on a branch and open a pull request; keep CLAUDE.md and PLAN.md up to date in it as usual. Don't run `tools/publish.sh` or `tools/pull-public.sh` here: they belong to the user's Mac, which brings merged PRs in with pull-public.

## Run and test

- **Start:** `uv run serve.py` (or the user double-clicks `Start Ostinato.command`, which does the same), then open http://localhost:8765 in **Chrome**. Safari has no Web MIDI. `uv run` reads the inline script metadata at the top of serve.py (Python ≥3.10, `anthropic`, `openai`). Plain `python3 serve.py` (macOS's 3.9) still works, with Claude Code as the only provider; keep `serve.py` and `ai_providers.py` 3.9-compatible and import the SDKs lazily.
- **Python on this Mac:** system 3.9.6; Homebrew's python@3.12 was broken on macOS 26.2 (pyexpat linked to a newer libexpat), so uv (Homebrew) supplies Python. Commands that create environments need the sandbox disabled (temp dirs).
- **Simulated synth:** http://localhost:8765/?sim (`tools/fakesynth.js`). Each page (editor, sequencer) loads its own simulated synth. It mirrors the real setup: ports named KBD/KNOB, SOUND, MIDI IN and MIDI OUT, global channel 2.
- **Tests:** `node tools/selftest.mjs`, and `python3 tools/providertest.py` for the AI providers (no AI is called). Covers the SysEx codec, the parameter map (bit fields, IDs), a round trip of all 512 factory presets through the AI value format, real-device reply bytes, and sound-type corrections. It also runs `tools/seqtest.mjs` (sequencer model and engine timing against a fake clock). Run it after any change to `js/params.js`, `js/aiparams.js`, `js/soundtype.js` or `js/seq/model.js` / `engine.js`.
- **Start/stop scripts:** `Start Ostinato.command` replaces any serve.py already listening on the port (waiting for a running AI design first), traps HUP/INT/TERM/EXIT to stop its uv and Python children (closing the Terminal window once orphaned the server for a day, so the page talked to stale code), and honours `MKXL_PORT` and `MKXL_NO_BROWSER` (for testing). `Stop Ostinato.command` stops the editor on the port.
- **Restarting the server:** first check no AI design is running (`pgrep -f "claude -p --output-format stream-json"`). Kill only the specific PID. Never `pkill -f serve.py` or `-n`: that once killed the user's server mid-design.
- **Commits:** commit after each feature with a descriptive message. The user relies on git history.

**User data lives in `data/`, its own git repo** (the app repo ignores it; `MKXL_DATA` can point elsewhere; `DATA` is defined in `ai_providers.py`). `init_data()` creates it with `git init` on first start. The server **auto-commits** it ~2 s after every save (`commit_data()`; uses the user's git identity, or a fallback), then `push_data()` pushes it in the background if the data repo has an `origin` remote (the user's: private git@github.com:judholliday/microkorg-xl-data.git). Pushes never prompt (BatchMode SSH); failures are logged and retried after the next save and at server start. Its `.gitignore` excludes `deleted/` folders and `settings.local.json` (API keys).
- `data/my-sounds/`: one `.syx` plus a `.json` note per sound. Removed sounds go to `deleted/`.
- `data/sequences/`: sequencer songs, one `.json` each (`/api/sequences`).
- `data/my-patterns/`: patterns saved with ★ (`/api/patterns`): `{name, role, tags, bpm, rate, mode, key, length, steps, pool?}`.
- `data/clips/`: the Recorder's clips (`/api/clips`; saving with `file` overwrites it): `{format: 'mkxl-clip', name, bpm, length, notes: [{pos, len, note, vel}] (ticks), sound, source}`.
- `data/ai-designs/`: one JSON per AI request (see below). `data/sound-types.json`: the user's sound types. `data/recovered/`: old recovered `.syx`.
- `data/settings.local.json`: AI provider settings and keys (git-ignored).
- The page fetches `/my-sounds/<file>` and `/sequences/<file>`, which serve.py maps to `data/`. It refuses to serve `data/`, `ai/`, `.venv/`, `settings.local.json` and any dot-path (`.git`, `.claude`).
- The data repo was split out of the app repo on 2026-10-04 with `git filter-branch`, keeping its history. **The app repo's old commits still contain the user's data**, so before publishing the app, publish fresh history (or rewrite it) rather than pushing this repo's history.

**Travel version (GitHub Pages):** the public repo's files served as a static site; no serve.py. `index.html` drops the XL editor frame and registers `sw.js` when STATIC; pages use `core/storage.js` for every file operation (never `fetch('/api/...')` directly, and only relative paths: Pages serves under `/<repo>/`). New page assets must be added to `sw.js` ASSETS. Test locally with a plain static server over a copy of the repo (e.g. `python3 -m http.server` in a folder containing the copy), opening `/<copy>/?static`.

**Publishing (public GitHub, MIT):** `tools/publish.sh` pushes HEAD minus its `EXCLUDE` list to the `github` remote (git@github.com:judholliday/ostinato.git) as a separate history, one commit per run; this repo's history stays local. Excluded: Korg's `.mkxl_all` banks and MIDI spec, the Minimoog charts (personal-use permission) and the Juno-106 data (from a GPL project). Add new not-shareable files to `EXCLUDE`. **Two-way with the public repo (Oct 2026):** work can also happen in the public repo (cloud sessions while the Mac is off, as pull requests). `tools/pull-public.sh` brings it here as one commit: the diff from the public commit last published or pulled (local ref `refs/published/github`) to the public repo's newest, applied three-way (a conflict stops with the files marked; fix, commit, then `git update-ref` as it prints). `publish.sh` refuses while the public repo has commits it hasn't seen, since publishing builds the tree from this repo and would undo them. Run pull-public before local work after merging PRs, and always before publishing. **Private backup of the whole app repo** (full history, Korg files, Juno-106/Minimoog): remote `private` = the data repo, branch `app` (`git push private main:app`). It isn't automatic; the user runs it (or asks for it) after work they want backed up. Tests skip sound-type corrections for banks that aren't installed.

**App data, tracked in the app repo:** `presets/`: Korg's factory banks (XL, plus Korg's conversions of the microKORG and MS2000 banks). For open source, these (and `docs/`, Korg's MIDI spec) should be downloaded by users from Korg instead.

## AI Designer and AI providers

`ai_providers.py` runs every AI request; `serve.py` builds it (instructions file, prompt, answer schema) and saves the result. Settings live in `data/settings.local.json` (gitignored, mode 600; keys never returned to the page). Providers:
- **claude-code**: `claude -p` with `--system-prompt-file`, `--setting-sources ""`, `--json-schema`; sound design gets read-only tools (Read, Grep, Glob, WebSearch, WebFetch) in `ai/`, patterns get `--tools "" --no-session-persistence` in `ai/patterns/`.
- **anthropic**: official SDK, manual tool loop (progress events, `pause_turn`), `output_config.format` json_schema (via `api_schema()`: closed objects, constraints stripped and re-checked by `check()`), adaptive thinking + effort on 4.6+ models, `web_search` server tool, server-side `fallbacks: "default"` (beta `server-side-fallback-2026-07-01`) on Opus 5.5 / Opus 5 / Sonnet 5.5 / Fable 5.1, cached system prompt. Default model `claude-opus-5-5`. Only tested up to authentication (no key on this Mac).
- **openai**: official SDK against any OpenAI-compatible base URL (OpenAI, Gemini, OpenRouter, Ollama, LM Studio, custom). Tool calls first, then the answer; `response_format` json_schema → json_object → plain fallback; answers parsed from text (fences, `<think>`) and re-asked up to twice if they don't fit. No web search.
- Sound design for API providers uses our own tools `search_presets` / `get_preset` over `ai/preset-index.md` and `ai/presets.jsonl`, and a list-of-pairs `changes` schema (`API_DESIGN_ITEM`) converted back to `{key: value}`.
- **Ollama facts (this Mac, 16 GB):** the OpenAI-compatible endpoint ignores `num_ctx`, and Ollama loads models with a 4096 context by default, which is too small (design prompt ≈ 9k tokens; thinking models spend 1-2k tokens reasoning). `_ollama_context()` reads `/api/ps` after the first reply and returns an explanation instead of a cut-off answer; `finish_reason == 'length'` is reported too. qwen3.6 (36B, 23 GB) swaps and times out; gemma4:12b fits but takes minutes.

- **Designs are saved in `ai-designs/`** (tracked), one JSON per request: `{time, request, mode, variations, current, session_id, status: running|done|error, error, results: [{base, name, changes, summary, hidden}]}`. The file is written when the request starts and updated with the answer; if the page disconnects, `_stream_claude` keeps reading so the result is still saved. `/api/designs` lists these (one entry per variation, key `"<file>|<index>"`); ✕ sets `hidden` in the file.
- **Old designs** were made before `ai-designs/` existed and only lived in Claude Code's session transcripts (`~/.claude/projects/-Users-jud-projects-microkorgxl-ai/`, cleaned up after ~30 days). `import_session_designs()` copied them in once (marker: `ai-designs/.imported`). Don't rely on session files for anything else.
- **Modifying a sound** resumes its Claude session (`--resume <session_id>`) on Claude Code. Other providers get the conversation's earlier requests as text (`conversation_so_far()`, from ai-designs/ files with the same `session_id`; API conversations get ids `conv-<first file stem>`). The page always sends the current settings too.
- **`--bare` can't be used:** it ignores the user's OAuth login.

## Hardware facts (verified on the user's synth, Oct 2026)

- **Firmware and channel:** firmware 1.04, global MIDI channel **2**.
- **Ports:** Chrome shows four. **KBD/KNOB** (in) and **SOUND** (out) are the synth. **MIDI IN/OUT** are pass-throughs to the 5-pin sockets. `findSynth()` probes every output and listens on every input.
- **Port names vary:** they've shown up short (`KBD/KNOB`) and full (`microKORG XL KBD/KNOB`, the user's Chrome in Oct 2026). Match on the suffix (`portLabel`, `looksLikeSynth*`). The simulator uses short names, so a port name saved while testing `?sim` won't match the real port: the sequencer falls back to a connected one.
- **USB is MIDI only:** no audio over USB. Recording the synth would need its outputs cabled into the user's Focusrite 2i2.
- **Chrome quirk:** with an update pending, Chrome passed notes through but silently dropped incoming SysEx. Relaunching Chrome fixed it. To check what the synth really sends, a CoreMIDI listener (Swift, built with `swiftc`) works alongside Chrome.
- **Confirmed working on hardware:** device inquiry, Korg search device, current-program dump (both requesting one and sending one into the edit buffer).
- **Listening (Oct 2026):** the XL's audio goes into Scarlett 2i2 **input 2**. `uv run tools/listen.py note [--patch '<AI-format JSON>']` sends a patch (init + changes, built by `tools/xlpatch.mjs`), plays a note on the SOUND port, records, and prints level, pitch (±0.01 c on steady tones), attack, release and brightness, plus a .wav and spectrogram .png in `recordings/` (gitignored). Needs the sandbox disabled (uv, MIDI, audio).
- **Calibration:** `caffeinate -i uv run tools/calibrate.py [tests]` measures amp EG times, cutoff in Hz, EG1 Int, OSC2 Tune and pitch-patch cents, and Analog Tune spread (resumable; results in `recordings/calibration.json`, copied to `docs/xl-measurements.json` and summarised in the AI prompt's "Measured units"). Use `caffeinate`: the Mac sleeping mid-run made the XL drop off USB (it needed replugging). The script stops if the synth goes silent.
- **More measured facts:** EG1 Int adds about 2 cutoff steps per unit in the cutoff knob's own units, not octaves (so the same amount opens fewer octaves from a low cutoff). Key Track +1.00 = full tracking centred on C4. Vibrato = mod wheel × LFO2 (100 = ±98 c at full wheel). The filter doesn't self-oscillate without input (and only faintly with a little noise).
- **Measured so far:** the program's Octave setting does not shift notes arriving over MIDI (Transpose does). The synth plays about +0.3 cents sharp. Record with the XL plugged **directly** into the Scarlett: through the user's mixer the level crept up over ~0.3 s after each note, the tone dulled and drifted, and levels were ~20 dB lower. Direct, the init saw at amp level 127 is steady (brightness ±0.1%) with about 63 dB above the noise floor.
- **Not yet confirmed on hardware:**
  - Parameter Change byte order and value encoding. The spec contradicts itself; `calibrate()` infers the encoding from knob messages.
  - Write to slot.

## Quirks found in Korg's data and spec

- **Program size:** the spec says 342 bytes, but its tables add up to 346. The editor sends back whatever length it received.
- **Split point:** byte 14 is undocumented but holds the split key, e.g. SYN DRUM = 61 (C#4). Timbre 1 plays below it, Timbre 2 at and above. It has no Parameter Change ID, so changes always go out as a whole program.
- **Chorus "LFO Spread":** factory presets often store 146, outside the documented 64±18. Values are displayed clamped, and raw bytes are only rewritten when the user or AI changes that setting.
- **Repeated table values:** the Time Ratio table repeats 100% five times, so tests compare meaning, not bytes.
- **Garbled spec tables:** T06-8 and T02-1 are garbled in the spec; the clean versions are in `params.js`.
- **PCM/DWGS wave names** are in the owner's manual, not the MIDI spec. They're shown by number for now.

## Sequencer notes

- **Timing:** a Worker drives `engine.pump()` every 25 ms (page timers are throttled in background tabs). MIDI goes out with `send(data, timestamp)`; the test synth converts the same timestamps to AudioContext time. UI highlights are scheduled with `setTimeout` to the note's time.
- **Stop** sends note-offs for sounding notes plus CC 123 per used channel, and FC to clock targets. Chrome has no way to cancel already-timestamped messages, so notes inside the 120 ms look-ahead still play.
- **Local Control** lives in the XL's Global data (byte 5, bit 7), which can only be changed with a full Global dump. The sequencer deliberately doesn't touch it; the user sets it on the synth or turns off **Thru**.
- **Song files** store output ports by name (`out`), or `computer` for the test synth. Not-connected ports show as "(not connected)" and play nothing.
- **Pattern buttons:** in loop mode they set `track.pattern` (saved) and queue the switch for the next bar while playing. In song mode they only change which pattern is shown for editing.
- **AI patterns** (`/api/pattern`): `claude -p` with `tools/pattern_prompt.md` as the system prompt, `--tools ""` (no tools), `--no-session-persistence` (so they never show in the AI Designer's Recent designs), and a schema of N options × the requested patterns (plus `pool` for note-pool tracks). The page builds the task text and a JSON context (tempo, swing, scale, this track's settings and, for "vary", its steps; other tracks' shown patterns when "fit" is on). Answers go through `cleanPattern(..., { onlyBelow: length })`. `MKXL_PATTERN_MODEL` overrides the model. Typical time 15–40 s.
- **Ideas** (`views[ti].ideas`): one list per track, filled by `addIdeas()` from the AI, the header 🎲 (`js/seq/generate.js`, no AI: Euclidean rhythms + scale + role) and the library. Same target patterns → appended (max 12); new target → new list and a fresh `before`. Each pick is one undo step; Original restores `before`; Keep clears the list; Put in copies to another pattern. The AI panel's 🎲 Surprise me = `generate(ti, { surprise: true })`, which ignores the description and lists earlier summaries so new ideas differ.
- **Drum styles:** `js/seq/styles.js` `STYLES` (skittering, five-beat, breakbeat, half-time, 2-step, motorik, footwork, 12/8 bell, glitch, jungle, math rock, dub, wonky): lane templates (`X x o ? g r p .`, or a function for rule-made lanes) of `steps` length, plus suggested bpm/swing/meter shown in the summary (never applied). The AI panel's **Style** (drum tracks; `ai.style`, default `any`) drives both 🎲 (`randomIdea({ style })`) and the AI task (`styleTask()`). Styles describe feels; they must not transcribe records.
- **Time signatures:** song `meter` ('7/8'…, `METERS`) and optional section `meter`; `barTicks`, `meterAt`, `songTicks`, `stepsPerBar` in model.js. The engine's bars use `barLength()` (section's meter in song mode); the metronome resets at each bar and clicks per beat unit (quarters in x/4, eighths in x/8); count-in = one bar of the first meter; the .mid file gets a time signature at each change (`renderSong().meters`). Pattern lengths aren't changed (a toast says how many steps make a bar). Capture's take editor and take-to-track still count 4/4 bars.
- **Feel (humanise):** track `feel` = `{time, vel, shift, push: {note: ms}, preset?}` (`cleanFeel`, null when empty; `FEEL_PRESETS`); the engine applies `feelNote()` per note (with its seeded `rng`, so .mid export repeats), moving notes ± and varying velocity; the pattern isn't changed. UI: Feel menu + Adjust… panel (`feelHTML`, per-drum push on drum tracks). Styles may suggest a feel in their summary.
- **Polyrhythm / polymeter:** pattern `beats` (Fit menu by Length) spreads its steps over that many beats: the engine schedules step k of a pass at `loopStart + round(k · span / length)` (`spanOf`), so passes last exactly their beats; no swing on fitted patterns. Pattern `laneLen` ({note: steps}, the small menu on each drum lane) loops that drum on its own length, counted by `ts.count` (steps since the pattern started, reset wherever `pos` is reset) via `stepGroups()`. The Polymeter style sets lane lengths itself (`loops`). Ideas, takes and breeding keep the original pattern's `beats`/`laneLen`/`cc` (`keepLanes`, `withShape`).
- **Breeding** (`js/seq/breed.js`): 🧬 (track header and Ideas bar) = `mutate()` of the pattern on screen; ⚭ Cross with = `cross()` of it and another idea (or the original). Drums work per lane (flip/shift/ratchet/chance; the kick on 1 and on-beat backbeats are kept; crosses take each drum from one parent, at least one from each); melodic patterns move notes by scale steps and cross by half bars. Results go through `addIdeas`, so Original and the other ideas stay.
- **Per-drum velocity:** a step's optional `nv` ({note: vel}, only notes that differ from `vel`) keeps ghost notes quiet beside louder drums; `velOf(s, n)`, `drumStep(i, [[note, vel]])` build/read it; the engine, the lane grid (⇧-click accents one drum) and stock patterns use it; editing a step's velocity clears it. The AI answers per-drum velocity as `vels` (aligned with `notes`), plus optional `prob`/`rat`.

Notes played just before their step are put in `rec.skip` so the engine doesn't replay them immediately. All notes in one run share one undo step (`changed({ coalesce: 'rec' })`).
- **Capture (now in the Recorder):** every MIDI in event (note on/off, CC64) is stored in this browser's IndexedDB (`core/kv.js`, key `rec.capture`; moved from localStorage once, Oct 2026), the newest `prefs.keepTakes` takes (25–200, default 50; `prune()` after each take ends), not by age, so playing isn't lost when you leave. A take is "synced" only if all its notes come from one playback run.

## Lab notes

- **Patch format first:** the patch is plain data so the UI, the AI (next step) and any future engine (e.g. Rust) share it. Add a module type by adding it to `MODULES` (params + targets) and a branch in `engine.js` `buildVoice` (voice scope) or `buildGlobals` (global scope); `normalizePatch` handles validation generically (voice→global audio allowed, not the reverse; no audio loops; mod targets must be declared).
- **Engine details:** pulse = sawtooth + constant offset through a hard comparator WaveShaper (offset = 2·pw−1, modulatable). Pitch and cutoff modulation go into `detune` (cents), so amounts are in cents. Amp = env gain → level gain (tremolo can't leak after release). Every voice→out/global connection goes through an `exit` gain so notes can be cut without clicks (voice stealing, rebuilds). `setPatch` copies the patch; settings-only changes update sounding notes, structural ones (modules, connections, osc wave, filter slope) cut notes and rebuild effects. Pitch bend ±2 semitones, CC 1 = wheel source, CC 64 sustain (in the page).
- **Patch diagram details:** target dots come from each module's `MODULES[type].targets` (`layout().dots`); `defaultTarget(type)` (patch.js) is where a modulation dropped on a box goes. While dragging, the svg gets `dragging-audio`/`dragging-mod` and valid ports/dots get `valid` (from `audioDestinations` / `modTargets`). `m.off` = bypass: in the engine, non-source in/out modules become a pass-through gain, sources (`isSource`) and modulators are skipped, global effects connect input→output; it's part of `setPatch`'s shape, so toggling rebuilds.
- **Waveforms:** `LabSynth.enableScopes()` (only the Lab page calls it) taps every audio module's output (all notes summed) and the instrument output into AnalyserNodes (`synth.scopes`, id → analyser, `'out'`). ui.js `scopeFrame()` runs only while a note is held (`synth.holding()`), drawing two cycles of the lowest held note (zero-crossing trigger) into each box's `[data-wave]` path (scaled to fit, ≤4×), plus `#scope-wave`/`#scope-spec` canvases under the diagram; on release the last picture stays (`waves-held`, restored after re-renders unless the patch's shape changed). - **Pad sounds:** a pad's `lSound` is `{name, patch}`, a copy of any Ostinato Synth sound (picked with the sound picker, `instruments: ['synth']`); `normalizePatch(p, { nested: true })` cleans it and drops sounds inside it (no endless nesting; drums.js gets the cleaner passed in to avoid a circular import). `LabSynth.loadSamples()` renders each with `renderSound()` (an OfflineAudioContext, note held `lHold`, tail trimmed) 120 ms after settings stop changing and keeps it in `samples` under `padSoundKey(p)`; `drumHit` plays it like the sample layer. `synth.ready()` waits for every sample and pad sound (the pad waveform, ▶ after a change, Bounce). **⤓ Bounce** renders a whole pad into a recording and replaces its layers with that sample (⌘Z restores them).
- **String module** (voice source, `ost-string` in fxworklet.js, one AudioWorkletNode per note): Karplus-Strong waveguide per string (fractional-delay allpass whose phase delay at the fundamental tunes it exactly; dispersion = `dispersion(f0, B)`: 0–16 identical first-order allpasses (24 below 50 Hz), M and coefficient fitted per note to partials ≤2.5 kHz, 1/k weighted, cached; B = `pianoB(note)` × (2·Stiffness)², so Stiffness 0.5 = a concert grand (B 1e-4 at C2, 7.5e-4 at A#4, 1e-2 at C8); measured within a few cents C3–C7, ~30% too stretched in the lowest octave, a one-pole low-pass fitted per note (at 3 kHz) so decay is per second, not per pass: the fundamental fades 60 dB in Decay, a 2 kHz partial in Highs, others by the square law rate = r0 + c·(F² − f0²) (Chaigne & Askenfelt / Bensa); Key → decay 1 scales Decay and Highs (given for C4) across the keyboard by `AFTER` (Martin's aftersound T60s) and `HIGHS` (that + Bensa's b3); Highs replaced Damping in Oct 2026 and `normalizePatch` migrates saved sounds with highs = decay / (1 + 30·damping), the same ring at 2 kHz; a per-pass filter made C7 die 10× too fast). **Coupling** (2–3 strings): after each string's loop filters, all subtract cpl × their sum (a yielding bridge), so strings moving together lose an extra Coupling × `PROMPT(f)` dB/s (the prompt sound) and once detuning moves them apart they ring at Decay (the aftersound); `PROMPT` is half Martin's prompt-minus-aftersound rates, because coupling also slows the drift apart: measured, Coupling 1 follows Martin's two-stage curves within ~3–6 dB over 8 s from C1 to C7, and the per-partial extra loss matches Bensa's b3 within ~1.3× (C3–C5). Pianos no longer need an Amp envelope). **Damper** (`damperFor`): when damped the loop keeps its normal losses and reads three taps (centre ± period/7), a zero-phase filter 1 − α(β + (1−β)sin²(ωD/2)), β 0.15: partials with a node under the damper (every 7th) ring on (measured ~40 dB/s vs ~400), α set from the fundamental and capped at 1 (above, partials between the nodes flip sign and ring). **Phantom partials** (Phantom): the square of the strings' common (bridge) signal, DC removed, × `PHANTOM` (5e-4: measured C2 ff ~11 dB below partial 8, pp ~27 dB), plus that square through a Q 60 resonance 4700 cents up (first longitudinal mode, only below ~C5). **Una corda** (`unacorda` option from `LabSynth.setPedal('soft')`, CC 67): the hammer strikes one string fewer with K × 0.5 and the last string gets no excitation (it picks up through the coupling): measured 1–3 dB quieter, darker, stronger aftersound (Bank: ~1 dB), excitation pluck/pick (filtered noise) or hammer (`hammerForce()`: a nonlinear felt hammer F = K·compression^p simulated at 2× rate against the string's impedance with the agraffe reflection; mass/K/p/Z interpolated from Chaigne & Askenfelt's C2/C4/C7; velocity = hammer speed 0.5–5 m/s, Brightness = felt hardness; contact ~3.5→3 ms at C2, ~1.8→1.5 ms at C4, <1 ms on top; strike point 1/8 moving to ~1/14 above A4; levels follow the physics, not normalised), comb at the strike Position, Knock (hammer only) = 0.4 × Knock × the hammer's force added straight to the output (Bank: soundboard input = string + 0.2 × hammer force), 1–3 strings with Detune (unequal weights, randomised detune and tiny onset offsets, so they beat without cancelling: equal, in-phase strings cancelled ~40 dB at 2 s), `damp` param = the damper (Damper time) set at release (legato can take it back via `relParams`). It starts at `processorOptions.start` (sample-accurate, for scheduled notes) and stops processing once rung out. Tuned within 1 cent from A1 to A6. Silent until the worklet has loaded (loadSamples starts it). Used by the pianos, harpsichord, clav, guitars, harp and Finger Bass in keys.js.
- **Soundboard** (global effect, `soundboardImpulse()` in engine.js → ConvolverNode): ~300 modes (grand: from 45 Hz, ~13 Hz apart; upright: from 85 Hz, sparser, boxier), Q 25–60 up to 100 Hz, falling as 100/f above (≥6), ring ≤0.45 s × Ring, plus a direct part (a filtered impulse) as strong as all the modes (options `direct`, `qfall`): with sharp modes everywhere and no direct part every note swelled for 50–80 ms after the strike and the attack sounded soft (user, Oct 2026); now notes peak 1–11 ms after it. Hammered notes start 0–2.5 ms late at random, since struck together their sharp attacks summed to 4–6× a note's peak (now ~2×), levels set per third-octave band to a target curve (rise to the lowest mode, bump near 300 Hz, roll-off above Tone); stereo = mid board ± side board (sides above 300 Hz only, so mono sums cleanly); levelled so tones pass at about their own level. Piano patches go string → amp → soundboard → reverb. Why: the bare string was the main reason the Grand sounded like a wire/toy (Bank: adding the soundboard and hammer knock was the biggest perceptual gain). Still missing for a real piano: phantom partials and longitudinal modes, sympathetic/pedal resonance, dampers that miss some partials, una corda. A/B renders: `recordings/piano/`.

## Loudness of converted libraries

`tools/loudness.mjs` estimates a program's loudness at C4 from its settings (oscillator spectra and levels, a 24 dB/oct filter at the measured cutoff Hz plus EG1 Int, amp level and EG2 sustain): `node tools/loudness.mjs [bank…]` prints each bank's median. It's a model, not a measurement, but it matched what the user heard (Oct 2026: Minimoog −13 dB, Juno −10, Polysix −7 vs Korg XL factory −3 → "very quiet, some silent").
- Every converter calls `levelProgram(changes, lost)` last: oscillator/noise levels up together (keeping the mix) to 127, then amp level, aiming at the factory median (−3 dB). Only a program inaudible even at its envelope peak (< −24 dB; an inverted EG1 counts at its sustain) gets its cutoff raised, in small steps until audible, and the report says so. Don't open filters to match loudness: patches that open bright and close are meant to.
- After levelling: Prophet −3.6, Polysix −5.0, Juno −6.2/−6.9, Minimoog −6.5. The rest of the gap is darker, single-oscillator sounds (true of the originals too).
- Minimoog cutoff is now referenced to the lowest key (F, ~1.6 octaves below C4) with keyboard control, like the Prophet's C2; at middle C most charts' filters were otherwise fully closed.
- Not yet checked on hardware: with the Scarlett connected, `tools/listen.py` could measure each bank against the factory sounds.

## Prophet-5 library

`presets/Prophet5_1978.syx` (bank "Prophet5_1978") holds the 38 original 1978 Prophet-5 factory programs converted to the XL. Rebuild it with `node tools/prophet/convert.mjs`, which also writes `tools/prophet/report.md` (per program: oscillator mapping, the settings, and what didn't carry over).
- `tools/prophet/factory-1978.json`: the patch sheets transcribed (MIDI.org's scans of the original manual). Every sheet was read twice independently and averaged; only 3 knobs differed by more than half a step, all on controls with no effect. Pitches come from the sheets' notes ("up 2 octaves plus a fifth"), not the knob drawings: the frequency dial's printed scale is uneven (2.5 = +1 oct, 4.5 = +2, 6 = +3, 8 = +4).
- `convert.mjs` uses the hardware measurements (`docs/xl-measurements.json`) for the XL side. The Prophet side's ranges are partly assumed and marked ASSUMED in the file: envelope times, cutoff reference (lowest key = C2), filter-envelope octaves, poly-mod depths, and "up 2 octaves" = written pitch. Tune those and rebuild.
- Mapping rules: Prophet Osc A goes on XL OSC2 when it's synced or poly-modded (OSC2 is the XL's sync slave and has the "OSC2 Tune" patch target), on OSC1 when Osc B FMs it (cross-mod modulates OSC1). Only OSC1 has pulse width. The Prophet LFO is LFO2 (the XL's Vibrato uses LFO2); lo-freq Osc B is LFO1 with key sync Voice. Self-oscillating-filter patches become a sine at the ringing pitch.
- `node tools/prophet/audition.mjs <program>` prints one program's settings for `listen.py --patch`.

- Juno-106 data (`tools/juno/juno106-factory.json`): the 18 patch bytes per program (16 sliders, SW1, SW2) from the GPL KR-106 emulator project (source unstated), decoded with Roland's MIDI implementation chart (manual p. 35).
- Mapping: pulse on OSC1 (pulse width), saw on OSC2 or OSC1, sub on OSC2 an octave down or the Wave Shape SubOSC when both oscillators are used; HPF = Filter 2 in series; the single ADSR copied to EG1 and EG2; chorus I/II = XL Chorus at 0.5/0.83 Hz, 50% wet, 180° spread. Juno-60 "manual" LFO trigger = the mod wheel. LFO delay = EG3 opening the LFO patch. Self-oscillating-filter patches (Juno-60 bank 7 and several 106 effects) become a sine.
- Types are in `js/sound-types.js`, from the Roland names.

## Korg Polysix library

`presets/Polysix_Charts.syx` (64), built by `node tools/polysix/convert.mjs` from `tools/polysix/charts.json` (report in `tools/polysix/report.md`). Source: Korg's official Polysix Setting Charts (two series of 32, A-1 to D-8; which series was in the factory memory isn't stated). Values are printed in the knobs; two independent readings agreed on all 1,472 values. Mapping: VCO on OSC1 (Pulse Ctrl1 = width, Ctrl2 = PWM by LFO1 at the PWM speed), sub on OSC2 1 or 2 octaves down, one EG copied to EG1/EG2 (gate mode = organ amp), MG on LFO2 (VCO/VCF/VCA, delay via EG3), effects: chorus/ensemble = XL Chorus, phase = XL Phaser. ATTENUATOR is a signed level trim (−4 … +10). Unison sounds (by name) use the XL's unison; chord memory isn't possible.

## Minimoog library

`presets/Minimoog_Charts.syx` (49), built by `node tools/minimoog/convert.mjs` from `tools/minimoog/charts.json` (report in `tools/minimoog/report.md`). Source: Moog's 1974 Minimoog Sound Charts (Tom Rhea), courtesy drtomrhea.com. **Licensing:** personal use; redistribution needs Tom Rhea's permission. The booklet isn't in the repo; review whether to ship the transcribed data before publishing the app.
- Read twice independently. Contour dials run 1 ms … 600 ms then 1, 5, 10 s, so printed 1/5/10 were resolved by pointer angle (all times stored in ms). Where a starred oscillator setting disagrees with the interval the notes ask for (the dials are approximate), the notes win.
- Mapping: mono (Mono 1); two heard oscillators in Timbre 1, a third in Timbre 2 as a Layer with the same filter/contours (no polyphony cost on a mono synth). Pulse widths need OSC1. Filter contour = EG1, loudness = EG2; DECAY switch off = quick release. Modulation (osc 3 in LO range, or noise) = LFO2 via the mod wheel: Vibrato for oscillator modulation, a wheel-opened LFO2 -> cutoff patch for filter modulation. Audio-rate osc-3 FM becomes an LFO. Ringing-filter sounds (Siren, Whistlers, Vree Oo) become a sine. Mixer overload = Drive.
